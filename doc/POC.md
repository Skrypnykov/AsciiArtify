# AsciiArtify — ArgoCD PoC

## 1. Мета

Мета цього Proof of Concept (PoC) — перевірити технічну можливість розгортання GitOps-системи на базі **ArgoCD** для проєкту **AsciiArtify** у Kubernetes-кластері.

У межах PoC необхідно виконати такі завдання:
* Розгорнути локальний Kubernetes-кластер
* Встановити GitOps-систему ArgoCD
* Перевірити коректність роботи та стан компонентів ArgoCD
* Налаштувати безпечний доступ до графічного вебінтерфейсу (ArgoCD UI)
* Скласти покрокову інструкцію для команди щодо авторизації в системі

---

## 2. Обраний Kubernetes-інструмент

Для локального розгортання в межах PoC обрано інструмент **k3d** — легковагове рішення для запуску Kubernetes-кластерів на базі дистрибутиву `k3s` у Docker-контейнерах.

### Причини вибору k3d:
* **Максимальна швидкість:** миттєве створення та видалення локального кластера
* **Ресурсоефективність:** мінімальне споживання оперативної пам'яті та CPU порівняно з повноважними аналогами
* **Ідеально для MVP:** чудово підходить для демонстрації GitOps-процесів та швидкого тестування
* **Стандартизація:** повна підтримка базових Kubernetes-інструментів та маніфестів

## 3. Передумови

Перед початком роботи переконайтеся, що у вашому локальному середовищі або у **GitHub Codespaces** встановлено такі інструменти:
* Docker (або сумісний container runtime)
* k3d
* kubectl

### Перевірка версій інструментів:
```bash
docker --version
k3d version
kubectl version --client
```

---

## 4. Створення Kubernetes-кластера

1. Створіть локальний кластер з назвою `asciiartify`:
   ```bash
   k3d cluster create asciiartify
   ```

2. Перевірте, що кластер успішно створений та готовий до роботи:
   ```bash
   kubectl cluster-info
   kubectl get nodes
   ```

*Очікуваний результат:* Локальна нода має перебувати в статусі `Ready`.

---

## 5. Встановлення ArgoCD

1. Створіть окремий namespace для ізоляції компонентів GitOps-системи:
   ```bash
   kubectl create namespace argocd
   ```

2. Встановіть ArgoCD, використовуючи офіційні стабільні маніфести:
   ```bash
   kubectl create -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
   ```

> 💡 **Примітка:** У цьому PoC свідомо використовується команда `kubectl create`, а не `kubectl apply`. Це дозволяє уникнути відомої помилки `metadata.annotations: Too long`, яка часто виникає під час спроби застосувати apply до великих Custom Resource Definitions (CRD) ArgoCD.

3. Перевірте статус запущених компонентів:
   ```bash
   kubectl get pods -n argocd
   ```

*Очікуваний результат:* Усі подове середовище ArgoCD має перейти в статус `Running`.

## 6. Налаштування доступу до ArgoCD UI

Під час проведення PoC як робоче середовище використовувався **GitHub Codespaces**. Для коректного прокидання портів (port forwarding) та відкриття вебінтерфейсу сервер ArgoCD було переведено в незахищений HTTP-режим (`insecure HTTP mode`). 

> ⚠️ **Важливо:** Таке налаштування допустиме виключно для демонстраційних цілей та локального тестування (PoC/MVP) і не має застосовуватися у Production-середовищі.

1. Увімкніть insecure-режим через конфігураційну мапу:
   ```bash
   kubectl patch configmap argocd-cmd-params-cm -n argocd \
     --type merge \
     -p '{"data":{"server.insecure":"true"}}'
   ```

2. Перезапустіть deployment сервера для застосування змін:
   ```bash
   kubectl rollout restart deployment argocd-server -n argocd
   kubectl rollout status deployment argocd-server -n argocd
   ```

3. Запустіть порт-форвардинг на адресу `0.0.0.0`:
   ```bash
   kubectl port-forward --address 0.0.0.0 svc/argocd-server -n argocd 8080:80
   ```

   *Альтернативний запуск у фоновому режимі (Background mode):*
   ```bash
   nohup kubectl port-forward --address 0.0.0.0 svc/argocd-server -n argocd 8080:80 > /tmp/argocd-port-forward.log 2>&1 &
   ```

4. Перевірте доступність порту локально:
   ```bash
   curl -I http://localhost:8080
   ```
   *Очікуваний результат:* `HTTP/1.1 200 OK`

### Покроковий доступ через GitHub Codespaces:
1. Перейдіть на вкладку **Ports** у нижній панелі VS Code.
2. Знайдіть у списку порт `8080`.
3. Натисніть кнопку **Open in Browser** (іконка глобуса).

## 7. Отримання пароля адміністратора

* **Початковий логін за замовчуванням:** `admin`
* **Отримання пароля:** Пароль генерується автоматично та зберігається в Kubernetes secret. Декодуйте його за допомогою команди:
  ```bash
  kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo
  ```

## 8. Вхід в ArgoCD UI

Використовуйте отримані дані для авторизації на відкритій у браузері сторінці:
* **Username:** `admin`
* **Password:** `<пароль_отриманий_з_команди_вище>`

Після успішного введення даних відкриється повноцінний графічний інтерфейс ArgoCD, готовий до деплою застосунків.

---

## 9. Фінальна перевірка працездатності

Щоб переконатися, що GitOps-платформа функціонує стабільно, виконайте фінальний моніторинг ресурсів:
```bash
kubectl get pods -n argocd
curl -I http://localhost:8080
```
Усі сервіси мають відповідати кодом `200 OK`, а вебінтерфейс повинен успішно приймати з'єднання через прокинутий порт Codespaces.

## 10. Результати PoC

У процесі виконання Proof of Concept було успішно реалізовано такі етапи:
* Розгорнуто швидкий локальний кластер Kubernetes за допомогою інструменту k3d.
* Конфігуровано та розгорнуто ArgoCD в ізольованому просторі імен `argocd`.
* Проведено перевірку внутрішніх компонентів та подів системи.
* Налаштовано тимчасовий insecure-доступ для демонстрації інтерфейсу всередині GitHub Codespaces Ports.
* Успішно отримано та розшифровано початковий секрет адміністратора, виконано тестовий вхід у вебпанель управління.

> 🚀 **Висновок:** Платформа ArgoCD повністю готова до наступного кроку розробки — реалізації та автоматизації повноцінного GitOps MVP для проєкту **AsciiArtify**.
